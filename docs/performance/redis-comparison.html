Why lists gain less (≈3×) than detail (≈6–7×)

  • 2 Redis calls per list: GET products:list:version, then the list key. Detail needs 1.
  • Bigger payload: 10–20 products to parse and send again, versus 1.

Why random IDs (D) are as fast as one hot item (C)

Only 185 products: after the first ~185 requests every detail is cached for 60s. With a large catalog, D would have more cache misses than C.

The load generator and the server run on the same laptop, so compare the ratios, not the absolute numbers. Errors in both runs: 0.
