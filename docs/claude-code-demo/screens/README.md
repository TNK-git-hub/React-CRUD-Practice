# Screenshots

Generated by `npm run screens` (`scripts/screenshots.ts`): an in-memory server driven by Playwright through the real UI
(dealer submits on Quick Apply, the customer consents on the phone pages, Ops issues the IPA then the AA with Change
Status). The script also clicks the "Demo: see …" buttons (they must open the same application in the other role) and
a Demo Control "Open sample" shortcut, and checks where they land. Desktop 1280 px wide,
phone 390 px. The design screens are `../design/*.dc.html`.

## Differences from the design

**Changed on purpose**

1. NRICs are masked everywhere (`F****488P`) with a "Show" link (audited, D-41); the design shows full NRICs.
2. Customer link check (05a): no NRIC row and no "Only the person with NRIC S****345Z…" sentence (no personal data on
   the customer pages). The design's "Other state" panel is a separate screen (05b).
3. Simulated Singpass login (06b): a list of the 9 test personas replaces the "Open Singpass app" button (the presenter
   has to pick a persona); footnote "In this demo the ValueMax gateway and Singpass are simulated…" (D-51). The gateway
   landing (06a) and review (08a) pages follow `singpass-reference/` (no design). Steps are numbered 1–3 of 3.
4. Consent (07): only the names of the requested items, as in `singpass-reference/3` and `/4`; the design shows values.
5. No text about retrieving vehicle documents through LTA (D-51, Proposal §3.1): removed from the Review & Submit
   banner (02) and from the Interest Received text (03), which the design still has.
6. Interest Received (03): no QR button (option after Release 1, D-51); extra "Go to My Applications" (prototype) and "View
   Application Status" buttons next to the design's "Submit Another" and "Demo: see what the hirer gets" (which opens
   this application's hirer link, D-50).
7. Quick Apply (01): label "Phone Number *" without "(for WhatsApp updates)" (Round 2 J1, D-51); "Fill sample (test
   personas)" button and an "Add a second guarantor" toggle inside the guarantor box.
8. Ops details (11*): status chip next to the reference, "Correct NRIC / email" button, link history with "no longer
   valid" labels, "Activity" log (the design shows a single red note), extra MyInfo rows (D-49). The "Cannot issue AA
   yet" box lists only the Singpass condition of each person; the design's "Mandatory documents accepted" and "FI Review
   completed" lines are not shown (D-10, D-11).
9. Ops list (10): "Expired links (n)" and "Demo Control" buttons instead of "+ New Application"; a second guarantor is
   listed under the first one. Search and filters, APPLICATION DATE column and the prototype's column names (D-57).
11. Prototype alignment of 2026-11-20 (D-52 … D-58, `../GAP_REPORT.md` §8): Review & Submit has the Dealer Declaration,
   the applicant declarations and three ticks (02); the dealer tracker has four steps, the last one named after the
   outcome (09*); the Ops details follow the prototype's block order, with the LTA Access Code masked (11*).
10. "Demo time: +N h" bar above the header on presenter screens while the clock is moved (12, 13); not in the design.
11. Expired links list (12) and Demo Control (13) have no design; they reuse the same components. Demo Control keeps a
    "QR (presenter only)" link as a fallback to open a link on a phone.
12. Dealer tracker: when the AA is issued without an IPA, the IPA step reads "No IPA — the AA was issued directly"
    (D-11); 09e shows the usual order (IPA, then AA).

**Not built (kept as differences)**

13. Customer email (04): the screenshot is the email body only; the design draws it inside a mail-client frame.
14. Ops list: no search box or filters (out of scope, brief §12). Ops details: no bottom bar (Cancel, FI Review
    Completed, Decline, Save — out of scope); vehicle make / model "—"; car plate "—" for new applications.
15. Header: a "Switch role" button (D-08) the design does not have.

The three "Demo: see …" buttons of the design are built (D-50). The dealer sidebar matches the design (Home /
Application / Account).
